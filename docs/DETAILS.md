# 解析の詳しいルール

BveRefViewer がファイルをどう読んで、どう判定しているかの詳細です。普段使うだけなら読む必要はありません。
「なぜこのファイルが出る/出ないのか」を知りたいときや、開発に参加するときの参考にしてください。

## ファイルの種類の判定

参照元のキー名 → ファイル先頭のヘッダー → 拡張子 の順で判定します。
ヘッダーは大文字小文字を区別せず、後ろに続く `,,,,` は無視します。

| ヘッダー | ファイル名 | 種類 |
|---|---|---|
| `BveTs Vehicle Performance Table` | `Force` を含む | 性能曲線(引張力テーブル) |
| 〃 | `Current` を含む | 性能曲線(電流テーブル) |
| 〃 | `Param` か `Prmtr` を含む | 性能曲線(進段パラメーター) |
| 〃 | 上記以外 | 性能曲線 |
| `BveTs Motor Noise Table` | `Vol` を含む | モータ音テーブル(ボリューム) |
| 〃 | `Freq` を含む | モータ音テーブル(周波数) |
| 〃 | 上記以外 | モータ音テーブル |
| `BveTs Vehicle Sound` | | 車両サウンドファイル |
| `BveTs Vehicle Parameters` | | 車両性能ファイル |
| `BveTs Instrument Panel` | | 運転台パネルファイル |

- ファイル名で決まらない表(`p-f.csv` など)は、参照元の行のキー名(性能曲線ファイルの `Force =`、モーター音ファイルの `Volume =` など)で判定します。
- ヘッダーの無い表も、性能曲線・モーター音ファイルから参照されていれば表として扱います。
- ATSプラグインと DLL は、CPU 種別を付けて「ATSプラグイン(x86)」「DLL(AnyCPU)」のように表示します。

## 車両側の参照のたどり方

BVE の車両関係ファイルはどれも「キー = 相対パス」か「1行1パス」の形なので、種類ごとの専用パーサーは持たず、
次のルールで解析しています([RefScanner.cs](../src/BveRefViewer/RefScanner.cs))。

- `;` `#` `//` 以降はコメント、`[...]` はセクション。値を `|` `,` で区切り、拡張子の付いたものをパスとみなします。
- 車両ファイル・サウンドファイル・性能曲線など、値が必ずパスになるキーは拡張子が無くてもパスとして扱います。
- 相対パスは参照元ファイルのフォルダが基準です(BVE の仕様どおり)。
- 文字コードは BOM → ヘッダーの `:UTF-8` 等の指定 → UTF-8 として読めるか → Shift_JIS の順で判定します。
- 同じファイルが複数か所から参照されているときは、最初の1か所だけ中身を展開し、他は「(上で展開済み)」と表示します。

### ATSプラグインの設定ファイル

DLL と同じフォルダにあり、**名前が DLL と対応する**設定ファイル(ini/txt/csv/xml 等)だけを
「同じフォルダの設定ファイル」として子に付け、その中に書かれたパスもたどります。

| DLL | 付ける設定ファイル |
|---|---|
| `Sample.dll` | `Sample.ini`(同じ名前)、`Sample_Effects.ini`(`DLL名_～`) |
| `Sample64.dll` | `Sample.ini`(ビット数表記 `64` `_x64` `_x86` 等を除いた名前) |
| `ConstSpdCtrl.dll` | `ConstSpd.ini`(DLL名の先頭部分。3文字以上) |
| `keisei_x64.dll` | `keisei_x64.txt` だけ(DLL名そのままの設定があれば、`keisei.txt` のような短い名前のものは付けない) |

- 名前が対応しない ini(例: `ATS.ini`・`TIMS_Spec.ini`)は付けず、「未参照ファイル」に出ます。
- README・NOTICE・LICENSE・りーどみー・更新履歴・マニュアルなどの説明書きは、名前が対応していても表示しません。
- 同じフォルダにある車両ファイルなど、BVE本体の形式(`BveTs ～` ヘッダー)のファイルも対象外です。
- ini に `..\IC` のようなフォルダ指定があれば、フォルダの中身を一覧として子に付けます(中身のファイルは読みません)。
- RealAnalogGauge の `Gauge0 = SPD` のように拡張子なしで名前だけ書かれた値は、同じフォルダに `SPD.ini`・`SPD.csv` 等が
  実在すればその参照とみなします。

### プラグインをまとめるプラグイン

| プラグイン | 読むファイル |
|---|---|
| DetailManager / ATS Plugin Multiplexer | `detailmodules.txt` に書かれた DLL を子プラグインとしてたどる。子プラグインのビット数も確認する |
| PluginOrganizer | `PluginOrganizer.dll` は `Instructions.yml`、`PluginOrganizer64.dll` は `Instructions64.yml` だけ。`run` の引数を子プラグインとしてたどり、`copy` のコピー元はフォルダとして中身を表示。v1.0(`- run x.dll`)と v1.1(`- cmd:` の下に並べる形)の両方に対応 |
| PluginConverter | `PluginConverter*.dll` と同じ名前の XML だけ。`<DLL><Path>～</Path></DLL>` の DLL を ATS プラグインとしてたどる(`<!-- -->` 内は無視) |

### AtsEX

次のどちらかがあれば、車両に「(AtsEX使用)」と表示します。

- **Caller 方式**: `AtsEx.Caller.x86.dll` などの入口 DLL。`AtsEx.Caller.txt`(AtsEX 本体のフォルダの場所。1行目を DLL のフォルダ基準で解決し、
  無ければ警告)と `AtsEx.Caller.x86.VehiclePluginUsing.xml`(AtsEX プラグイン一覧)だけを読みます。
- **車両フォルダ方式**: 車両ファイルと同じフォルダの `VehiclePluginUsing.xml`(または `車両ファイル名.VehiclePluginUsing.xml`)。

一覧の `<Assembly Path="～.dll" />` を「AtsEXプラグイン」としてたどります。AtsEX プラグインは .NET の DLL なので、
ATS プラグインの関数の検査はしません。`AtsEx64` のようなフォルダ名だけでは AtsEX とはみなしません。改名後の `BveEx.Caller` も同じ扱いです。

## ATSプラグインのチェック

- **ビット数**: `Ats` と `Ats32` に x86、`Ats64` に x64 の DLL が指定されているか。子プラグインは親と同じビット数かを調べます。
- **エクスポート関数**: BVE が呼ぶ関数が DLL からエクスポートされているか。
  - 1つも無い(DllExport の処理に失敗して .NET の DLL のまま、など)→ 警告
  - `GetPluginVersion` か `Elapse` が無い → 警告
  - `Load`・`Dispose` などそれ以外だけが無い → 警告しない(それでも動いている配布プラグインがあるため)。
    個々の関数の有無は、DLL を選ぶとプレビュー欄に ✓/✗ で出ます。

## 対応する BVE の判定

| ATSプラグインの指定 | 判定 |
|---|---|
| x86 のプラグインだけ(`Ats` か `Ats32`) | BVE5専用 |
| x64 のプラグインだけ(`Ats64`) | BVE6専用 |
| 両方 | 両対応 |
| なし(車両ファイル 2.00 以降) | 両対応 |
| なし(車両ファイル 1.00 以前) | BVE5専用(BVE6 は BVE5 以前のシナリオをプレイできないため) |

- 指定されたプラグインが見つからない・ビット数が違うときは、その側を × にします。
- 車両ファイル 2.00 形式で BVE5 が ○ のときは、「BVE 5.8 が必要」と注記します。

## 車両フォルダ・路線フォルダ(外部ファイルの判定)

- **車両フォルダ**は、基本は車両ファイルのあるフォルダです。車両ファイルが `Vehicle_txt` のようなサブフォルダにあり、
  直接の参照の半数以上が1つ上のフォルダに収まる場合は、そこを車両フォルダとします(2階層以上は上がりません)。
- **路線フォルダ**は、シナリオのフォルダの直下にある、路線のマップが入ったフォルダです(例: `Scenarios\YamatojiLine`)。
- これらの外にあるファイルは「外部」として灰緑色で表示し、「概要」で外部ライブラリとしてまとめます。

## 路線(マップ)

マップから他のファイルを読むのは次の文だけなので、マップ構文を全部は解析せず、この文だけを拾います(速さのため)。

| 文 | 表示される種類 |
|---|---|
| `include '～';` | 路線(マップ)。さらにたどる |
| `Structure.Load('～')` | ストラクチャーリスト(`キー = .xのパス`) |
| `Signal.Load('～')` | 信号現示リスト |
| `Sound.Load('～')` / `Sound3D.Load('～')` | サウンドリスト / 3Dサウンドリスト |
| `Station.Load('～')` | 停車場リスト |
| `Train.Add('キー', '～', …)` / `Train['キー'].Load('～', …)` | 他列車ファイル |

- マップ内のパスは、include されたファイルの中でも**最上位のマップファイル**のフォルダが基準です。
  リストファイルの中のパスは、そのリストファイルのフォルダが基準です。
- `$名前 = '～';` と文字列が代入された変数を使うパスもたどります。`'local_' + ceil(rand(3)) + '.txt'` のように
  実行時まで決まらないものはたどらず、「値が決まらない変数での参照 n 件は未確認」と表示します。
- `#`・`//` 以降(引用符の外)はコメントとして無視します。
- `include '<AtsEx::MapPluginUsing>～.xml';` は AtsEX のマッププラグイン一覧としてたどり、
  `include '[[AtsEx::NOMPI]] ～';` は無視します。
- 1つの文が複数行に分かれて書かれている場合は拾えません。

### テクスチャ

「テクスチャも確認」がオンのとき、テキスト形式の .x(`xof 0302txt`)の `TextureFilename { "～"; }` を読み、
.x のフォルダ基準で画像の有無を確認します。マテリアルがどの面で使われているかは見ていないため、
使っていないマテリアルの画像も対象になります。バイナリ形式・圧縮形式の .x は確認できません。

## コマンドライン(確認・開発用)

```
BveRefViewer.exe <ファイル>
    起動してそのファイルを開く(exe にファイルをドラッグ&ドロップしたのと同じ)

BveRefViewer.exe --dump <シナリオか車両ファイル> <出力.txt> [--textures]
    画面を出さずに、参照ツリーと概要をテキストに書き出す(--textures でテクスチャも確認)。
    車両データを変更した前後で出力を比べれば、参照の変化を確認できる。

BveRefViewer.exe --shot <シナリオか車両ファイル> <出力.png> [ファイル名の一部 または -] [動作] [--textures]
    画面を画像に保存して終了する(表示の確認用)。
    動作: parent        選んだファイルの参照元の行を表示して撮る
          summary       「概要」タブを表示して撮る
          tab数字       その番号のタブ(0始まり)を表示して撮る
          during        読み込み開始の約1秒後(読み込み中の表示)を撮る
          cancel        約1秒後にキャンセルして撮る
          reload-cancel 読み込み後に再読み込みし、0.5秒後にキャンセルして撮る
    --shot では「最近のファイル」と「テクスチャも確認」の設定は書き換えない。
```
